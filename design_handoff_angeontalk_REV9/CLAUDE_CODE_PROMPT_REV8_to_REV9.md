## 👇 여기서부터 Claude Code에 붙여넣기

안건톡(건설 현장 업무 메신저) 기존 구현(REV8)에 REV9 변경분을 추가해줘.
REV9는 현장 상세 진입 구조를 **도면 중심에서 탭 구조로 확장**하고, 신규 **공정현황 대시보드** 화면과 **하청업체 공정 참여 요청·승인 흐름**을 추가하는 작업이다.
REV9 디자인 레퍼런스: `design_handoff_angeontalk_REV9/anrgeontalk_wireframes_rev9.html` (모든 화면이 iPhone 390×844 프레임으로 한 문서에 배치, CSS는 `<style>`에 인라인, 화면 하단 `<script>`에 순수 JS 인터랙션).

기존 다크 테마, Pretendard 폰트, "상태 배지에만 색을 쓰는" 원칙, 큰 터치 타깃, 한글 UI를 유지하고, REV8까지 확정된 화면·레이아웃·색상·플로우는 건드리지 말 것.

상태색(공통): 검토중 주황 #f59e0b / 조치중 파랑 #3b82f6 / 완료 녹색 #22c55e / 사전검토 보라 #8b5cf6 / 관찰중 하늘 #0ea5e9. 브랜드 액센트(옐로우) #ffd60a는 CTA·포커스 한정.

**대시보드 화면 자체는 표시 전용 목업**이지만, 공정 추가 요청·승인·입력창 화면은 **실제 흐름(화면 전환·상태 변화)까지** 구현한다. 서버 저장·데이터 영속화는 이번 범위 밖.

### 배경 지식
- 건축·전기·통신·소방 4개 공종만 시공사로 등록되고, 그 외 공정(철근콘크리트·철골·외장판넬 등)은 이 4개 시공사 아래 하청으로 참여한다.
- 회원가입(별도 REV) 구조가 이미 존재한다는 전제 위에서, **하청업체 소장이 현장·공정을 등록하면 원청 시공사 소장에게 알림이 가고 승인**하는 흐름을 다룬다.

### REV9 변경 요약

**1. 현장 상세 진입 구조 변경 (레퍼런스 화면20)**
- REV8 현장 상세 화면 상단에 탭 2개 추가: **도면 / 공정현황**. 기본 선택은 도면(REV8 기존 화면 그대로).
- 공정현황 탭 → 신규 대시보드로 전환. 탭 UI는 **기존 프로필 상세 화면의 탭 스타일(`.pf-tabs`) 재사용**.

**2. 공종 표시 체계 + 공유 색상 팔레트**
- 건축·전기·통신·소방 4개는 시공사가 있는 한 항상 고정 표시(fixed). 하청 공정(철근콘크리트 등)은 **승인을 거쳐 추가**되며 리스트·도넛 구간에서 아래로 늘어나는 구조.
- 각 공종은 시스템 자동 배정 고유 색상을 가지며, 이 색상은 **도넛차트·공정현황 리스트·도면 야적/작업 레이어 범례에서 동일 공종이면 어디서나 같은 색**으로 쓰인다(단일 팔레트 소스 공유 — 레퍼런스: `TRADE_COLORS` 상수).

**3. 신규 화면 — 공정현황 대시보드 (세로 스크롤, 4구간)**
- **① 최상단 요약:** 좌상단 D-데이(예: D-481) 크게. 아래 착공~준공 기간 진행바(양끝 날짜, 중앙 위 % 크게). 그 아래 공정율 섹션 — 좌측 전체 합산 도넛(중앙 %), 우측 계획(청록)·실행(파랑) 가로 게이지 2개 세로 배치, 구간 우상단 기준일.
- **② 주별 실적:** 상단에 공종별 표(공종 / 전전주누계 계획·실적·달성율 / 전주 주간·누계 계획·실적·달성율 / 비고), 하단 합계 행 강조. 표 아래 막대+선 복합 차트(회색막대=주간계획, 노란막대=주간실적, 회색선=누계계획, 빨간선=누계실적), 좌상단 범례, 가로 스크롤로 전체 공사기간 주차 수용, 좌축=주간%/우축=누계%.
- **③ 공종별 현황:** 세로 카드(이름·달성율%·계획대비실적 한 줄·작은 진행바·좌측 배정색). 목업: 건축·전기·통신·소방 + 하청 철근콘크리트. 우상단 "공정 추가 요청 보기" 플러스 버튼(대기 요청 개수 배지).
- **④ 공종별 도넛:** ③의 공종마다 작은 도넛 2열 그리드(중앙 %, 하단 공종명, 색상=배정색).

**4. 신규 화면 — 공정 추가 요청 알림·승인 목록**
- 원청 시공사 소장 계정 화면. 대기 요청 리스트(신청 업체명·신청자 이름/직급·신청 공정명·신청 일시 카드). 탭 시 상세로.

**5. 신규 화면 — 공정 추가 요청 상세·승인**
- 신청 정보(업체명·신청자·공정명·현장명·신청 일시)를 명함 형태로. 하단 승인/거절 큰 버튼. 승인 → 확인 다이얼로그("○○ 공정을 현장에 추가하시겠습니까? 승인 시 해당 업체가 공정률을 직접 입력할 수 있게 됩니다") → 확인 시 완료 피드백 + **대시보드에 해당 공종 추가 반영**.

**6. 신규 화면 — 공정률 입력창**
- 승인된 하청 담당자가 본인 공종 카드 진입. 상단 공정명·기준일. 주간계획/주간실적/누계계획/누계실적 4개 숫자 입력 + 하단 저장 버튼. **REV9는 화면·입력 UI까지만** — 실제 저장(타 화면 반영) 로직은 다음 REV로 이월(주석 표기).

### 데이터 / 상태 모델 (REV9 추가분)
- **Site**: 착공일·준공예정일·기준일 필드 추가.
- **Trade(공종)**: 이름, 배정 색상(자동), 고정 여부(4대=true), 승인 상태(고정=approved / 하청=요청 후 approved 또는 pending).
- **ProcessSummary**: 공종별 전전주누계 계획·실적, 주간 계획·실적, 누계 계획·실적 시계열.
- **TradeRequest(공정 추가 요청)**: 신청 업체명, 신청자 이름·직급, 신청 공정명, 현장명, 신청 일시, 상태(대기·승인·거절). 목업 대기 요청 1~2건.

### 구현 지침
- REV8 코드 구조/컴포넌트 패턴/상태관리/디자인 토큰 소스를 그대로 따라 신규 화면·상태 추가.
- 탭 전환은 기존 프로필 상세 탭 패턴 재사용. 공종 색상 자동 배정은 REV8 야적·작업 레이어 색상 지정 방식과 **같은 팔레트 소스 공유**로 설계.
- **차트 라이브러리는 도입하지 않는다** — 도넛은 CSS conic-gradient, 복합 차트는 SVG 직접 렌더(의존성 0, 다크테마 정합).
- 승인·거절·저장 등 액션은 로컬 상태 변화까지만. 변경 후 REV8 화면 회귀 없는지 확인.
