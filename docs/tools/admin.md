## 기능
간섭·정합 결과와 현장 질의를 담당·기한·상태로 관리하고 RFI 문서를 만듭니다. 모델에서 대지·건축·연면적을 계산해 건폐율·용적률·높이·정북일조를 검토하고 건축개요를 만듭니다.

## 데이터
- 읽기: P.clash, P.check, P.content, P.sheets, P.levels, P.site
- 쓰기: P.issues, P.code
- 다른 트랙에 제공하는 함수: `issue.js` → `addIssue(P, o)`, `TYPES`, `STATES` (clash·check·cad·view3d가 사용) / `code.js` → `computeCode(P, opts)`, `resolveLimits(C)`, 법령 데이터(`LAWS`, `ARTICLES`, `LEGAL`, `ORDINANCES`, `PENDING`, `LAW_CHECKED`)

## 법령 데이터 갱신 절차
- 데이터는 `app/tools/code.js`의 `법령 데이터 BEGIN ~ END` 블록에만 있습니다. 판정 로직과 분리돼 있어 이 블록만 고치면 됩니다.
- 주 1회 예약 작업이 국토계획법·건축법(시행령 포함)의 시행일·공포번호, 입법예고 진행 상황을 점검합니다. 바뀐 게 있으면 블록을 갱신하고 `LAW_CHECKED`를 올린 뒤 `[admin] vN: 법령 갱신 — …`으로 PR을 올립니다.
- 원문(국가법령정보센터)으로 확인하지 못하고 2차 출처로만 확인한 값은 `verify: true`로 둡니다. 화면에 "원문 대조 필요"로 표시됩니다.
- 앱 실행 중에는 법령을 조회하지 않습니다(CORS·API 키 문제). 법령 기준일이 45일을 넘으면 화면에 경고가 뜹니다.
