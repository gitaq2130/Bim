# 지속 가능한 수익 전략

> 이 문서는 "Claude를 써서 어떻게 지속적으로 돈을 벌 것인가"에 대한 실행 계획이다.
> 시장 자료가 아니라 **현재 실제로 보유한 자산**에서 출발한다.

---

## 0. 핵심 명제

> **내가 Claude로 "일을 대신 처리"하는 동안에는 소득이 내 시간에 비례한다. 지속 불가능하다.**
> **지속 가능해지는 지점은, Claude로 만든 산출물이 다시 팔 수 있는 자산(스킬·코드·템플릿)으로 남을 때다.**

여기서 나오는 단 하나의 운영 규칙:

> **같은 일을 3번 하면, 3번째에는 반드시 스킬/스크립트로 만든다.**
> 스킬은 비용이 아니라 **재고(inventory)** 다. 한 번 만들면 팔 때마다 원가가 0에 수렴한다.

이 규칙을 지키느냐 아니냐가 "AI로 일 빨리 하는 사람"과 "AI로 돈 버는 사람"을 가른다.

---

## 1. 현재 보유 자산 실사

### 1-A. 문서 자동화 스킬 5종 — **이미 현금화 가능**

| 스킬 | 대체하는 수작업 | 검증 상태 |
|---|---|---|
| 회의록 자동 작성 (녹취 → DOCX, 발주처 지시사항 강조) | 회당 2~3시간 | 실무 사용 중 |
| 하도급계약 검토·확인서 (별표5 기술자 배치 자동 산정) | 건당 반나절 | 실무 사용 중 |
| 문서관리대장 누락 대조 (TFA/TFR) | 건당 1~2시간, 실수 잦음 | 실무 사용 중 |
| 휴일작업계획서 취합 (협력사별 → 1장) | 휴일마다 1~2시간 | 실무 사용 중 |
| 아웃룩 주간 회의안내 자동발송 (공휴일 대체 로직) | 매주 반복 | 실무 사용 중 |

**이게 가장 저평가된 자산이다.** 이유:
- 이미 작동한다 (개발 리스크 0)
- 고객이 이미 존재한다 (같은 일 하는 CM단/감리단/공무팀이 전국에 있다)
- 효과를 숫자로 증명할 수 있다 ("회의록 3시간 → 15분")
- 유통 비용이 0에 가깝다

### 1-B. 안건톡 — **자산이지만 아직 상품이 아님**

되어 있는 것: 화면 전체, UX 흐름, 안드로이드 빌드 파이프라인, 아티팩트 번들러

**되어 있지 않은 것 (냉정하게):**
- 실서버 없음 — Firebase는 `lib/firebase.ts`에 초기화만 되어 있고 실제 호출 0건
- 인증/계정 없음
- 실시간 메시지 동기화 없음 (localStorage 단일 기기)
- 푸시 알림 없음
- 파일/사진 스토리지 없음
- **AI 요약이 실제 AI가 아님** — 시드 데이터
- 6개월 추적 스케줄러 없음

즉 **투자자·발주처 앞에서 시연할 수 있는 최상급 목업**이지, 아직 파는 물건이 아니다.
이걸 인정하고 시작하는 게 중요하다. 이 갭을 메우는 데 드는 시간이 곧 Tier 2의 원가다.

### 1-C. 도메인 포지션 — **복제 불가능한 진짜 해자**

- 삼성전자 고창CDC 물류센터 신축공사, 발주처–PM단(CM단) 라인
- 실제 대형 현장의 문서 양식·결재 흐름·발주처 요구 수준을 안다
- 개발자는 이 맥락이 없고, 현장 사람은 이걸 코드로 못 만든다. **둘 다 되는 사람이 드물다**

## 2. 3단계 수익 사다리

작은 현금흐름부터 만들고, 그 현금과 레퍼런스로 큰 걸 짓는다. 순서를 바꾸면 돈이 마르기 전에 제품이 안 나온다.

### Tier 0 — 문서 자동화 대행 (0~3개월) · **현금흐름 만들기**

**무엇을 파나:** 결과물(회의록·검토서·취합표)을 납품한다. 도구는 안 판다.

**누구에게:**
1. 같은 현장의 다른 공종/협력사 공무 담당
2. 아는 CM사·감리단 동료 (가장 빠른 첫 고객)
3. 중소 건설사 공무팀 — 전담 인력이 없어 이 일을 야근으로 때우는 곳

**가격 구조 (제안):**

| 상품 | 형태 | 근거 |
|---|---|---|
| 회의록 정리 | 건당 3~5만원 | 사람 2~3시간 인건비의 절반 이하 |
| 하도급 검토서 | 건당 10~15만원 | 반나절 + 법령 리스크 제거 |
| 문서대장 대조 | 월 20~30만원 | 누락 1건 = 감사 지적 |
| **현장 정액제** | **월 50~80만원 / 현장** | 위 전부 + 무제한 |

정액제로 유도하는 게 핵심이다. 건당 과금은 매달 영업을 다시 해야 한다.

**왜 이게 먼저인가:** 3개월 안에 현금이 돈다. Tier 2를 버티게 해주는 연료다.

**Tier 0의 함정 (반드시 경계):**
- 이건 **용역**이다. 매출은 여전히 내 시간에 묶여 있다
- 그래서 Tier 0의 진짜 목적은 돈이 아니라 **"어떤 문서가 반복되는지"의 데이터 수집**이다
- 고객 3곳이 같은 걸 요구하면 → 그게 Tier 1의 제품 스펙이다

### Tier 1 — 도구 판매 전환 (3~9개월) · **시간에서 분리되기**

**전환의 계기:** 대형 현장은 **발주처 자료를 외부로 못 보낸다.** 대행 모델의 천장이 여기다.

**그런데 이 제약이 정확히 세일즈 포인트가 된다:**

> "파일을 저희에게 보내지 마세요. **고객사 PC 안에서** 돌아가는 도구를 드립니다."

**상품 형태:**
- Claude Code + 스킬팩 설치형 (`.claude/skills/`)
- 회사 문서 양식에 맞춘 커스터마이징
- 초기 셋업 300~500만원 + 유지보수 월 30~50만원
- 또는 좌석당 구독

**핵심 이점:** 고객이 늘어도 내 작업시간은 늘지 않는다. **여기서 처음으로 소득이 시간에서 분리된다.**

**해야 할 일:** 스킬 5종을 남의 회사 양식에서도 돌아가게 일반화 + 설치 문서화.

### Tier 2 — 안건톡 SaaS (9~24개월) · **자산 만들기**

Tier 0~1이 **입구**고, 안건톡이 **그릇**이다.
문서 자동화로 들어간 현장에 "그 문서들이 쌓이는 곳"으로 안건톡을 넣는다. 콜드 세일즈가 아니게 된다.

**최소 판매 가능 제품(MVP)까지 남은 것 — 우선순위:**

1. Firebase Auth + Firestore 실연결 (현재 껍데기만) — **가장 크고 가장 먼저**
2. 실시간 메시지 동기화, 다중 기기
3. 사진/도면 스토리지
4. FCM 푸시
5. **AI 요약 실연결** (Claude API) — 이게 제품의 차별점, 지금은 시드 데이터
6. 6개월 추적 스케줄러

> 1~4는 "메신저면 당연한 것"이라 팔리는 근거가 아니다. **5번이 유일하게 카톡이 못 하는 것이다.**
> 개발 순서는 1→5를 먼저 붙여 시연 가능한 상태를 만들고, 2~4로 채운다.

**과금 모델 — 좌석당 과금은 실패한다:**
건설 현장은 협력사 인원이 매주 바뀐다. 좌석 관리가 고객에게 고통이면 안 쓴다.

> **현장(프로젝트) 단위 정액제.** 인원 무제한.
> 소규모 월 30~50만원 / 중대형 월 100~200만원 / 대형 별도

**첫 검증 경로 (이게 최단거리):**
1. 고창CDC 현장 1개에 무료 파일럿 — 협력사 3~4곳, 8주
2. 사용 로그로 증명: 안건 등록 수, 방치 안건 감소, 재발 방지 건수
3. 그 레퍼런스로 → 같은 발주처의 다른 현장 → 같은 CM사의 다른 현장

**대형 건설사 1곳 뚫기 > 중소 100곳 영업.** 건설은 레퍼런스 산업이다.

## 3. 하면 안 되는 것

| 유혹 | 왜 안 되나 |
|---|---|
| **카카오톡 대체 노리기** | 네트워크 효과와 정면충돌. 안건톡은 "카톡 대신"이 아니라 **"카톡에서 흘러가 버리는 결정을 남기는 곳"** 으로 팔아야 한다. 카톡과 병행 전제로 설계할 것 |
| **일단 무료로 뿌리고 나중에 과금** | B2B 건설에서는 안 통한다. 무료로 쓰던 걸 유료화하면 그냥 이탈한다. **처음부터 유료, 대신 파일럿은 기간 한정 무료** |
| **대형사 SI 커스터마이징 수주** | 당장 금액이 커서 제일 유혹적이다. 그런데 그 순간 제품이 아니라 **용역 회사**가 된다. 다음 고객에게 재판매가 안 되면 사다리가 끊긴다 |
| **기능 더 늘리기** | 화면은 이미 충분하다. 지금 부족한 건 기능이 아니라 **작동하는 백엔드와 첫 유료 고객**이다 |
| **회사 몰래 진행** | 아래 4항 참조. 이건 전략이 아니라 생존 문제다 |

## 4. 먼저 정리해야 할 리스크 (돈 얘기보다 이게 먼저다)

1. **직무발명·산출물 귀속** — 재직 중 업무 관련해 만든 결과물의 소유권. 취업규칙·근로계약서를 먼저 확인할 것. 나중에 터지면 사업 전체가 날아간다.
2. **겸업 제한** — 사규 확인. 필요하면 사업자 등록 시점과 형태를 조정.
3. **보안·기밀** — 발주처 도면, 계약금액, 협력사 단가는 **절대 외부 반출 금지**. Tier 1의 "고객사 PC 내 실행" 모델이 이 문제의 해답이자 세일즈 포인트다.
4. **판매용 데이터 분리** — 데모/샘플에는 실제 프로젝트명·금액·업체명을 절대 넣지 말 것. 지금 `lib/seed.ts`부터 점검 대상.

이 4개를 정리하기 전에는 외부 영업을 시작하지 않는다.

## 5. 90일 실행 계획

### 1~30일 — 증명과 정리
- [ ] 위 4항 리스크 확인 (취업규칙·근로계약서)
- [ ] 스킬 5종의 **시간 절감치 실측** — "회의록 3시간 → 15분" 같은 판매 근거 확보
- [ ] `lib/seed.ts` 실데이터 제거, 안전한 데모 데이터로 교체
- [ ] 안건톡 시연 영상 3분 (지금 목업으로도 충분히 찍힌다)

### 31~60일 — 첫 매출
- [ ] 아는 CM사·감리단 3곳에 회의록 자동화 제안 (무료 샘플 1건 → 정액 전환)
- [ ] **목표: 유료 고객 1곳** (금액보다 "돈을 받아봤다"가 중요)
- [ ] 병행: Firebase Auth + Firestore 실연결 착수

### 61~90일 — 사다리 연결
- [ ] Tier 0 고객 3곳 확보 → 공통 요구사항 추출 → Tier 1 제품 스펙 확정
- [ ] 안건톡 AI 요약(Claude API) 실연결 — 시연에서 "진짜로 요약된다"가 보여야 한다
- [ ] 고창CDC 파일럿 내부 제안

## 6. 스스로 점검할 질문

매달 이 세 개만 본다.

1. **이번 달에 만든 것 중, 다음 달에 다시 팔 수 있는 게 있는가?** — 없으면 아직 용역이다
2. **내가 일주일 손을 놓으면 매출이 0이 되는가?** — 예라면 Tier 1로 못 넘어간 것이다
3. **같은 작업을 3번 이상 반복했는데 스킬로 안 만든 게 있는가?** — 있으면 그게 이번 달 최우선 과제다

## 부록: Claude 활용 원칙

| 하지 말 것 | 대신 이렇게 |
|---|---|
| 문서 한 건 처리시키기 | 그 문서 **종류**를 처리하는 스킬 만들기 |
| 매번 새 프롬프트 쓰기 | 스킬로 고정 → 품질 균일화 → 남에게 팔 수 있음 |
| 코드 짜달라고만 하기 | 그 코드가 **재판매 가능한 모듈**인지 먼저 묻기 |

> 판단 기준 하나: **"이 결과물이 내일 다시 돈을 벌어주는가?"**
> 아니라면 그건 일한 것이지, 자산을 만든 게 아니다.
