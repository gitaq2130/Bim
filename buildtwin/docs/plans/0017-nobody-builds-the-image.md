## 1. 분석 — **이미지를 짓는 자리**와 **그것을 도는 주체**

### 1-a. 사이클 0016 이 남긴 자리

사이클 0016 은 `Dockerfile` 의 폴백을 지웠다(`c82cf47`). 그 트리의 설치 줄은 이렇다(**코드 인용 · 발췌**,
`git show 12a2d34:buildtwin/Dockerfile`):

```dockerfile
COPY pyproject.toml ./
# 설치의 정본은 pyproject.toml 하나다 — 의존성 이름을 여기 두 번째로 적지 않는다.
# 폴백을 두지 않는다 — 실패를 삼키고 두 번째 설치를 잇는 셸 OR 도, 조용한 기본값도.
# 이 설치가 실패하면 빌드는 rc 0 으로 끝나지 않는다(ADR 0020 §2-1 항 1).
RUN pip install --no-cache-dir -e .
COPY . .
```

**그 주석의 마지막 줄이 이 계획의 표적이다.** 「빌드는 rc 0 으로 끝나지 않는다」는 참이지만,
**그 rc 를 읽는 자리가 저장소에 없다.** 계획 0016 의 조건절은 「실패가 **소리내어** 죽는가」였고
그 계획이 정의한 「소리」는 **네 관측자 중 최소 하나에서 보이는 것**인데, 문 3 의 rc 는
**아무도 듣지 않는 소리**다 — 계획 0016 §확인하지 않은 것 **72·79** 가 둘 다 *"[재야 한다 → 사용자
또는 CI]"* 로 열린 채인 것이 그 값이다.

### 1-b. 전수 — 「이미지를 짓는 자리」 (§6-1 ①②③)

**① 생성 기준.** 저장소 루트에서, **이미지를 짓는 명령을 이름으로 부르는 줄**을 센다 — 표기 집합은
`docker compose build` · `docker compose up`(`--build` 를 달고) · `docker build` · `--build` 넷이고,
**경로로 먼저 좁히지 않으며 자기 커밋도 센다**(§53). 값(각 N=1, 트리 `12a2d34`):

| 명령 | 값 |
|---|---|
| `git grep -nIE 'docker[ -]compose (build\|up)' 12a2d34 -- .` | **33줄** |
| 같은 명령의 `buildtwin/docs/` **밖** 히트 | `buildtwin/Makefile:40` · `buildtwin/README.md:38` · `buildtwin/tests/invariants/test_demo_stack_can_stand.py:53` · `buildtwin/tests/invariants/test_the_first_run_names_its_doors.py` 의 `:35`·`:71`·`:73`·`:77`·`:85` |
| `git grep -nIE 'docker build' 12a2d34 -- .` | **0줄** |
| `git grep -nIE 'docker[ -]compose\|docker build\|--build' 12a2d34 -- .github` | **rc 1 = 히트 0** |

**그 히트들을 읽으면 갈래가 둘이다**(히트 수가 아니라 각 히트를 읽는다 — §6-1):
**실제로 명령을 부르는 자리는 `Makefile:40` 하나**(`docker compose up --build`)이고, 나머지는
**문서의 안내**(`README.md:38`)이거나 **테스트가 문자열로 붙드는 상수**
(`test_the_first_run_names_its_doors.py:85` 의 `DOOR_OPENING_COMMAND = "docker compose up"`)다.

**② 이 기준이 놓치는 것**(§6-1 ②).
- **ⓐ 짓지 않으면서 그 이미지에 기대는 자리** — 이 기준은 「짓는다」만 센다.
- **ⓑ 저장소 밖에서 짓는 자리**(사용자의 손 · 남의 CI · 배포 파이프라인). **사용자의 손이 그 자리다.**
- **ⓒ 보간·줄바꿈** — §6-1 역방향 확인 ③④ 그대로. 표기가 변수로 조립되면 문자열이 소스에 없다.
- **ⓓ 짓기의 *결과*에만 기대는 자리**(이미지 안에 무엇이 들어갔는가) — `openpyxl` 축이 그 모양이었다
  (계획 0016 §1-c 문 3).

**③ 블라인드 스팟을 한 건 태웠다 — ⓐ 를 태우니 자리가 났다.**
`git grep -nIE 'docker compose [a-z]+' 12a2d34 -- .` 의 `docs/` 밖 히트를 읽으면
`buildtwin/Makefile` 의 `seed-compose` 레시피가 **`docker compose exec -T api python -m services.api.seed`**
다(코드 인용). **그 명령은 이미지가 이미 있고 컨테이너가 떠 있다고 가정한다** — 짓는 명령이 아니라서
①의 목록에는 영원히 들어오지 않는데, **그 가정이 참인지 아무도 재지 않는다.**
(`tests/invariants/test_demo_stack_can_stand.py` 는 그 레시피의 **배선 이름**만 읽는다 — 그 파일의
머리 주석이 *"5 는 배선의 이름(어느 서비스·어느 명령)만 읽는다"* 라고 스스로 적는다, **인용 · 발췌**.)

### 1-c. 곱 표 — (이미지를 짓는 일 × 그것을 도는 주체) (§6-1: 관계를 세는 목록은 **곱**으로)

축은 **주체 넷**이다: **사용자**(첫 실행자) · **CI**(`buildtwin-ci.yml`) · **로컬 게이트**
(`make test`/`make lint`/`make e2e`) · **리뷰어**. ✔ = 그 주체가 실제로 돈다, ✘ = 돌지 않는다.
**각 칸은 실행값이거나 코드 인용이고 다른 절 참조가 아니다.**

| 일 | 사용자 | CI | 로컬 게이트 | 리뷰어 | 값 (각 N=1) |
|---|---|---|---|---|---|
| `docker compose config`(파일 해석) | ✔ | ✘ | **✔** | ✘ | `tests/invariants/test_demo_stack_can_stand.py` 가 `.env` 없이 rc≠0, `make env` 뒤 rc 0 을 붙든다(그 파일, 내가 읽었다) |
| **이미지를 짓는다**(`pip install -e .`) | **✔ — 유일하다** | **✘** | **✘** | **✘** | `.github` 에서 표기 집합 히트 **0**(§1-b) · 로컬은 데몬 rc 1 · `ip_forward` 0 |
| 스택이 뜬다(`up`) | ✔ | ✘ | ✘ | ✘ | 같은 값 |
| 시드가 그 스택에 닿는다(`exec`) | ✔ | ✘ | **△** | ✘ | 로컬 게이트는 **레시피의 이름**만 읽는다(§1-b ③) |
| 웹 번들을 짓는다(`npm run build`) | ✔ | **✔** | **✔** | ✘ | CI `:250` `run: npm run build` · `Makefile:92` `cd apps/web && npm run build`(`e2e` 가 의존한다) |

**곱이 만든 칸이 이 계획의 범위를 정한다.** **사용자만 ✔ 인 행**은 「이미지를 짓는다」·「스택이 뜬다」·
「시드가 닿는다」이고, 그중 **가장 앞의 문**이 「짓는다」다 — 짓지 못하면 나머지는 시작하지도
못한다. **그리고 마지막 행이 대조군이다**: 같은 저장소가 **웹 번들은 CI 와 로컬 게이트 둘 다에서
짓는다.** 파이썬 이미지만 사용자에게 남아 있다.

### 1-d. 한정어 역방향 확인 (§6-3 — **새로 쓰는 조건절도 예외가 아니다**)

이 계획의 조건절은 **「첫 실행의 이미지를 **사용자보다 먼저** 짓는 자리를 저장소에 둔다」** 다.
한정어마다 한 줄씩 답한다.

| 한정어 | 빼면 무엇이 더 들어오나 | 있어서 무엇이 빠지나 | 이 계획의 처분 |
|---|---|---|---|
| **첫 실행의** | 재빌드·캐시 무효화·업그레이드 경로가 들어온다 | **두 번째 빌드부터의 실패**(레이어 캐시가 감추는 것) | 범위 밖으로 **명시**한다(§1-e). CI 는 캐시 없는 러너에서 도므로 이 축은 오히려 CI 가 낫다 |
| **이미지를** | 스택 기동·헬스체크·마이그레이션까지 들어온다 | **뜨는가**(`build` ≠ `up`) — 컨테이너가 실제로 서는지는 이 조건절 밖이다 | 범위 밖. **§후속 77**(준비 상태 계약)과 한 자리이고, 이 계획은 그것을 닫지 않는다 |
| **짓는** | `config` 축·lint 축까지 들어온다 | 이미 붙들려 있는 것 — `docker compose config` 의 rc 는 불변식이 본다 | 잃는 것 없음(§1-c 첫 행이 ✔ 다) |
| **사용자보다 먼저** | 「언젠가 짓는다」가 들어온다 | **사용자가 이미 친 뒤의 재현** | 그것은 §확인하지 않은 것 **79** 이고 이 계획이 닫지 않는다 |
| **저장소에 둔다** | 남의 CI·개인 스크립트가 들어온다 | **저장소가 아닌 자리에서 도는 빌드** — 그것은 저장소가 붙들 수 없다 | 게이트를 **저장소 안**(불변식)에 둔다. 그 이유가 §1-e ⓑ 다 |

**옛 조건이 잡던 것도 묻는다**(§6-3). 계획 0016 의 조건절은 **「첫 실행 경로의 실패가 소리내어
죽는가」** 였고 그것이 잡던 것은 **문 1·2·3·6 의 관측 가능성**이다. 이 계획의 조건절로 바꾸면 그
자리들은 **전부 「통과」로 넘어간다** — 문 1·2 는 불변식이, 문 3 은 `Dockerfile` 의 rc 가, 문 6 은
vitest 가 붙든다. **잃는 것은 하나다**: 계획 0016 은 「소리」를 **네 관측자 중 최소 하나**로 정의했는데
문 3 의 관측자는 **rc 뿐**이고, 이 계획이 그 rc 를 **읽는 주체**를 만들지 못하면 그 정의는 문 3 에서
공허하게 참이다. **그러므로 이 계획은 계획 0016 의 조건절을 대체하지 않고 그것의 미완을 잇는다.**

### 1-e. 이 사이클의 범위

**닫는다**: ⓐ **CI 가 이미지를 짓는다**(사용자보다 먼저 도는 주체를 하나 만든다) ⓑ **저장소가 그
사실을 붙든다**(워크플로 선언을 읽는 불변식 — 그 잡이 사라지거나 조용히 건너뛰어지면 빨개진다).

**닫지 않는다**: 스택 기동(`up`)·헬스체크(§후속 **77**) · 시드가 실제로 닿는가 · 컨테이너 안의 프록시 ·
재빌드 경로. 근거 셋: ⓐ **곱 표의 가장 앞 문이 「짓는다」**이고 뒤의 것은 그것 없이 서지 못한다
ⓑ 기동을 CI 에 두면 **서비스 여섯**이 들어와 잡의 실패 원인이 갈리지 않는다(§6-2 1: 결함이 있어도
값이 같은 시나리오를 만들지 않는다) ⓒ 이 환경에서 **데몬이 없어**(rc 1) 기동 축의 실행값을 이 계획이
낼 수 없다. **셋 다 §후속으로 이름을 남긴다.**

**형식(§후속 55).** 각 인용에 **ⓐ**(그 자리에서 도는 참조)와 **ⓑ**(인용/재서술 · 전체/발췌)를 붙인다.

**작업 1 (qa · `.github/workflows/buildtwin-ci.yml`)**
1. **잡이 이미지를 짓는다.** `docker compose build`(또는 그와 같은 일을 하는 명령)를 부르고,
   **그 rc 가 잡의 rc 가 된다.** 확인: 그 스텝이 `continue-on-error` 를 갖지 않는다.
2. **짓기 전에 `.env` 를 만든다.** compose 의 `api`·`worker` 는 둘 다 `env_file: [.env]` 이고
   (**ⓐ** `grep -n "env_file" docker-compose.yml`, **ⓑ 코드 인용 · 발췌**), `.env` 가 없으면
   **파일 해석 단계에서** 죽는다(그 사실은 `tests/invariants/test_demo_stack_can_stand.py` 가 이미
   붙든다). **저장소에 `.env` 를 커밋하지 않는다** — 잡 안에서 `make env` 를 부른다.
3. **조용히 건너뛰지 않는다.** `if:` 로 그 잡을 끄는 조건을 두지 않고, `paths` 필터는 이미 워크플로
   전체에 걸려 있는 것을 그대로 쓴다(**ⓐ** `grep -n "paths:" ../.github/workflows/buildtwin-ci.yml`).
4. **다른 잡의 초록을 이 잡이 가리지 않는다.** 기존 넷(`lint`·`unit`·`integration`·`e2e`)의
   `needs` 를 바꾸지 않는다 — 빌드가 빨개져도 **다른 축의 값은 그대로 보여야 한다**(§6-2: 하나의
   실패가 다른 축을 삼키면 그 축은 관측되지 않는다).
5. **빨개지면 그것이 값이다.** 이 잡이 처음부터 빨간 채로 오면 그것은 회귀가 아니라 **계획 0016
   §리스크 1 이 예고한 발견**이다 — 그때 고칠 자리는 `pyproject.toml` 이지 이 잡이 아니고,
   **그 판정과 값을 커밋 본문에 이름으로 적는다.**
6. **거짓으로 만드는 남의 자리**: ⓧ `buildtwin/README.md` 의 §빠른 시작(소유 **없음**, §후속 19) 이

**작업 2 (qa · `tests/invariants/`)**
1. **잡의 선언을 읽는 불변식**이 셋을 단언한다: ⓘ 그 이름의 잡이 워크플로에 **있다** ⓙ 그 잡의 어느
   스텝이 **이미지를 짓는 명령**을 부른다 ⓚ 그 스텝·잡에 **삼키는 열쇠가 없다**

2. **양성 케이스가 결함 코드에서 값이 갈리는지 태운다**(§6-2 1). 변이는 **한 자리씩** 심고
   **심기 직전의 작업 트리 사본과 `diff`** 로 적용을 확인한 뒤 재고 그 사본으로 원복한다
   (§6-2 규칙 5 — **같은 커밋이 처음 넣는 줄을 지우는 변이는 `git diff` 가 침묵한다**).
   최소한 이 셋을 심는다: 잡을 통째로 지운다 · 짓는 명령을 다른 명령으로 바꾼다 ·
   `continue-on-error: true` 를 단다. **각 변이가 죽이는 단언의 이름과 값을 표로 남긴다.**
3. **탐침 자신을 태운다**(§6-2 5 — `test_the_first_run_names_its_doors.py` 의 Y5 가 그 선례다):
   워크플로를 읽는 경로가 틀렸을 때 **초록으로 지나가지 않는지**를 단언 하나로 붙든다.
4. **개수를 세지 않는다**(§6-1 9회차) — *"잡이 다섯이다"* 같은 문장을 쓰지 않고, 세는 대신
   **이름**과 **부재**를 단언한다.

6. **거짓으로 만드는 남의 자리**: `tests/invariants/test_demo_stack_can_stand.py` 머리의

   **낡는지 아닌지를 값으로 판정하고 커밋 본문에 적는다.**

## 리스크

1. **새 잡이 처음부터 빨갈 수 있다.** `Dockerfile` 의 `RUN pip install --no-cache-dir -e .` 가 통과하는지
   **아무도 재지 않았다**(계획 0016 §확인하지 않은 것 79). **그것이 이 작업의 목적이다** — 빨개지면
   그때 고칠 자리는 `pyproject.toml` 이고, **그 발견은 사용자가 아니라 CI 가 한다.** 다만 이 위험은

3. **불변식이 YAML 의 선언만 본다.** 잡이 있는데 **실제로는 아무것도 짓지 않는** 경우를 그 불변식은

4. **이 계획이 큐를 세 사이클 연속 민다**(§2 역방향 ⓐ). **그 자체를 §후속 86 으로 연다** —

**방법 · N · 표본 간격**(§후속 **34** · 27). 아래 값은 **2026-09-08 한 세션 안**(19:15~19:24 UTC,
`date -u` 로 앞뒤를 찍었다)에 잰 것이고, **따로 적지 않으면 N=1**, 서로 몇 분 간격이다.
**「없다」·「히트 0」에도 N 을 적는다.**

**저장소 밖 값의 출처**(§후속 **62**). 이 절은 **CI 잡 로그**의 값을 싣는다 — 그것은 저장소 밖이고

(`grep`·`sed`, 각 N=1), 그 사본은 **세션 스크래치패드에 있고 사라진다** — 저장소에 들어오지 않는다.
**로그 줄 번호는 그 사본의 것이다.**

**자원**: **docker 데몬 0회**(이 절은 데몬을 요구하는 값을 하나도 내지 않는다 — 러너의 값은 읽기만 했다) ·

(`ls -a <각 디렉터리> | grep -c '^\.env$'` → **0**, 각 N=1, 이 절의 앞과 뒤 둘 다) · 잡은 포트 없음.

#### 3-1-3. qa 의 「CI 잡에 대해서는 손해 0」 판정 — **확인했다. 로그도 그것과 맞다**

qa 가 워크플로 주석에 적은 문장(**ⓐ** `grep -n "러너와 함께 사라진다" ../.github/workflows/buildtwin-ci.yml`,
**ⓑ 인용 · 발췌**): *"**이 잡은 이미지를 푸시하지 않으므로** 그 레이어는 러너와 함께 사라진다."*

**㉮ 내가 그 YAML 을 다시 읽은 값**(`python3` 으로 파싱, N=1):

| 물음 | 값 |
|---|---|
| `image` 잡의 스텝 | `actions/checkout@v4` · `run: make env` · `run: docker compose build` — **그뿐이다** |
| 그 잡의 최상위 열쇠 | `name` · `runs-on` · `steps` · `timeout-minutes` — **`permissions` 도 `outputs` 도 없다** |
| 아티팩트로 나가는 자리 | 그 잡에 `upload-artifact` **없다**(있는 자리는 `unit`·`integration` 의 metrics 뿐) |
| 레지스트리로 나가는 자리 | 그 잡에 `login`·`push`·`docker save` **없다** |
| 워크플로 권한 | `permissions: contents: read`(`:27-28`, **ⓑ 코드 인용 · 발췌**) — **`packages: write` 가 없어 푸시할 권한 자체가 없다** |

**㉯ 로그가 같은 것을 말한다**(저장소 밖 · 출처 §3-0, 각 N=1): `grep -nEi "docker (push|login|save)|##\[group\]Run "` 의
히트는 **`Run actions/checkout@v4` · `Run make env` · `Run docker compose build`** 뿐이고
**push·login·save 는 히트 0** 이다. 산출물은 로컬 이름뿐이다(위 ㅍ).

**판정: qa 가 맞다.** 그리고 그 판정을 **더 싸게 만드는 축**이 하나 더 있다: 그 러너의 `JWT_SECRET` 은
**그 잡이 그 자리에서 만든 난수**이고 **아무것도 서명하지 않는다** — 사용자의 토큰도, 어떤 지속 DB 도
그 값에 매여 있지 않다. 즉 그 레이어는 **새지 않을 뿐 아니라 새더라도 아무것도 열지 못한다.**
두 축이 독립이라 하나가 틀려도 다른 하나가 남는다.

**그리고 「잡 로그로도 새지 않는다」를 값으로 쟀다**(§확인하지 않은 것 **91** 이 그 물음이다 —
*"`make env` 가 만든 난수 `JWT_SECRET` 이 잡 로그·아티팩트에 새는지 재지 않았다"*, **ⓑ 인용 · 발췌**):

| 축 | 명령(로그 사본, N=1) | 값 |
|---|---|---|
| 이름으로 | `grep -n "JWT_SECRET"` | **히트 하나** — `:135` 의 *"값은 출력하지 않는다"* 그 줄이다 |
| `.env` 를 읽는 줄 | `grep -n "\.env"` | **같은 한 줄뿐** — `cat`·`echo` 로 그 파일을 찍는 자리가 없다 |
| **값의 모양으로** | `grep -oE '[A-Za-z0-9_-]{43,}' \| sort -u` | 히트를 **전부 읽었다**: URL 슬러그 하나와 나머지는 **16진 다이제스트**다. `secrets.token_urlsafe(32)` 가 내는 **43자 base64url 모양은 없다** |
| 아티팩트 | 위 YAML 표 | 그 잡은 **아무것도 업로드하지 않는다** |

***한정***: 마지막 축은 **모양**으로 판정한 것이다 — 값 자신을 모르므로 그것을 직접 grep 할 수 없다.
「그 모양의 문자열이 로그에 없다」까지가 이 값이고, 「어떤 인코딩으로도 없다」는 아니다.

*역방향 확인 — 이 「손해 0」이 놓치는 것.* ⓐ **잡 로그는 러너와 함께 사라지지 않는다**(GitHub 이
보관한다) — 위 표가 그 축을 값으로 답했다. ⓑ **캐시**: 이 잡은 빌드 캐시를 저장·복원하지 않는다
(`cache` 열쇠 없음) — 캐시를 붙이는 편집이 오면 이 판정은 다시 재야 한다.

#### 3-1-4. **사용자의 기계에서는 그 이미지가 남는다** — 이것이 더 큰 축이다

경로는 README ② 다(**ⓑ 재서술**): `make env`(난수 `JWT_SECRET` 을 `buildtwin/.env` 에 쓴다) →
`make dev`(= `Makefile:40` `docker compose up --build`). **그 `--build` 가 같은 컨텍스트를 같은
`Dockerfile` 로 짓는다.** 러너에서 그 짓기의 산출물이 **`buildtwin-api`·`buildtwin-worker` 라는 이름의
로컬 이미지**였고(ㅍ), 러너에서는 그것이 기계와 함께 사라진다 — **사용자의 기계에서는 사라지지 않는다.**

**그리고 그 레이어는 실행에 쓰이지도 않는다.** `api`·`worker` 는 `volumes: [".:/app", …]` 로
**호스트 디렉터리를 `/app` 위에 덮는다**(`docker-compose.yml:43`·`:55` `volumes: [".:/app", "storage:/data/storage"]`, **ⓑ 코드 인용 · 전체**) —
그래서 `COPY . .` 가 넣은 `/app` 의 내용은 **뜬 컨테이너가 읽지도 않는다.**
**얻는 것 없이 시크릿만 굽는다**는 것이 이 자리의 값이다.

***한정 — 이 축은 아무도 재지 못했다***: 위 문단에서 러너가 답한 것은 **「짓기가 이름 붙은 로컬
이미지를 낸다」** 까지다. **사용자의 기계에서 그것이 남는가**(그리고 얼마나 오래)는 이 사이클이 재지
못했다 → **§확인하지 않은 것 98.** 판정이 갈리는 자리가 정확히 여기다.

3. **결정적 근거 — 게이트를 내가 쓸 수 없다.** `tests/` 의 소유는 `qa` 다. 내가 `.dockerignore` 만
   만들면 그것은 **게이트 없는 계약**이 되고, 그 실패 모양은 이 저장소가 이미 값으로 갖고 있다:
   *"계약이 있는데 게이트가 없으면 다음 편집이 그것을 조용히 지운다"*
   (`tests/invariants/test_ci_builds_the_image.py` 머리, **ⓑ 인용 · 발췌**) — 그 파일이 든 값이
   *"안내를 지워도 `123 passed` 로 무변화였다"* 이고, 같은 파일의 「이 파일이 서기 전」 표가

   똑같이 조용히 지워질 수 있다.**
4. **한 소유가 파일과 게이트를 함께 지는 것이 이 사이클의 축이다** — §작업 분배가
   *"작업 1·2 를 한 소유가 지는 것이 이 사이클의 축이다"* 라고 적었고(**ⓑ 인용 · 발췌**),
   작업 5 는 같은 모양이다.

*역방향 확인 — 이 판정이 놓치는 것.* ⓐ **배정은 실행이 아니다.** 작업 5 가 돌기 전에 사용자가
`make dev` 를 치면 그 기계에는 시크릿이 구워진 이미지가 남는다 — **그 창을 이 판정이 연다.**
그 창을 닫는 것은 순서뿐이므로 **작업 5 를 작업 4(마감)보다 앞에 둔다**(§다음에 부를 에이전트에
그 순서로 적었다). ⓑ 이것을 §후속으로 미루지 **않는 것**이 그 창에 대한 답이다 — §후속 **86** 이
이름 붙인 갈래에서 이것은 **① 이 사이클의 작업으로 삼는다** 쪽이다. ⓒ **위험의 크기는 내가
판단했다** — 「시크릿이 굽히는 것」을 「파생물이 통째로 전송되는 것」보다 앞에 뒀고, 그 순서를 뒤집을
값은 이 절에 없다. ⓓ **러너에서는 손해가 0 이므로**(3-1-3) 이 배정이 고치는 것은 **CI 가 아니라
사용자의 기계**다 — 러너의 컨텍스트는 이미 작다(5.78MB, ㅋ).

#### 3-1-6. **작업 5 (qa · `buildtwin/.dockerignore` + `tests/invariants/`)** — 이 절이 더하는 배정

> **소유가 아니라 배정이다**(§2). `.dockerignore` 는 소유가 없는 자리(§후속 19)이고, 이 사이클이
> `qa` 에게 **배정**한다. 근거는 3-1-5 의 3·4 다.

**완료 조건**

1. **`buildtwin/.dockerignore` 를 만든다.** 자리는 **빌드 컨텍스트의 뿌리**여야 한다 — 컨텍스트가
   `buildtwin/` 이므로(ㄷ) 저장소 루트에 두면 **아무 효과가 없다.** 그 자리가 맞는지는 러너가 이미
   이름으로 말했다(ㅈ: `load .dockerignore` 가 `worker`·`api` 의 **internal** 단계다).
2. **빼는 것을 이름으로 정한다**(개수를 적지 않는다 — §6-1 9회차). 축은 하나다:
   **「커밋하지 않는 것은 이미지에도 넣지 않는다」** — `.gitignore` 와 같은 축이고, 그래서 그
   목록이 이 목록의 뼈대다(**ⓐ** `git show 1e8fb19:buildtwin/.gitignore`).
   **반드시 들어가야 하는 이름**(각 이유와 함께):
   - `.env` · `.env.*` — **이 배정의 이유 그 자체**(3-1-2·3-1-4). `.env.example` 은 예외로 남긴다
     (`!.env.example` — `.gitignore` 와 같은 처분).
   - `.venv/` — 호스트의 가상환경. **2.4G**(ㅅ)이고 컨테이너의 인터프리터와 무관하다.
   - `node_modules/` · `apps/web/dist/` · `dist/` — 웹 파생물(**231M**). `api`·`worker` 는 읽지 않고
     `web` 컨테이너는 `node:22-alpine` **이미지**를 쓴다(`docker-compose.yml:58`, **ⓑ 코드 인용 · 발췌**).
   - `.mypy_cache/` · `.pytest_cache/` · `.ruff_cache/` · `__pycache__/` · `*.pyc` · `*.egg-info/` —
     호스트 도구의 캐시(**43M** 이상).
   - `storage/` · `*.db` — **런타임 데이터**. 오늘 이 트리엔 없지만(`ls` → absent, N=1) 사용자의
     기계에는 업로드 원본과 로컬 sqlite 가 그 이름으로 생긴다(`Makefile` 의 `db-reset` 이
     `rm -f *.db` 다, **ⓑ 코드 인용 · 발췌**).
   - `apps/web/.e2e-preview*.config.mts` — e2e 가 잠시 만드는 설정(`.gitignore` 마지막 줄).
   **이 목록 밖의 것은 컨텍스트에 그대로 남는다** — 그것이 이 목록이 기대는 **부재**이고, 특히
   `services/` · `packages/` · `config/` · `rules/` · `pyproject.toml` 은 **빠지지 않는다.**
3. **빌드를 깨뜨리지 않는지 정적으로 확인한다**(데몬 없이). `Dockerfile` 이 이름으로 `COPY` 하는 것은
   **`pyproject.toml` 하나**이고(ㄹ · 러너 로그 ㅌ 가 그 스텝을 이름으로 싣는다) 위 목록의 어느
   항목도 그 이름에 걸리지 않는다. `COPY . .` 는 남는 것을 넣는다 — 컨텍스트를 통째로 비우는
   패턴(`*`)을 쓰지 않으므로 빈 COPY 가 되지 않는다. **`pip install -e .` 은 `COPY . .` 보다
   앞이라**(러너 로그: `#10 … COPY pyproject.toml ./` 가 `#12 … COPY . .` 보다 앞) **이 목록의
   영향을 받지 않는다.**
4. **게이트를 함께 만든다**(3-1-5 의 3). 불변식이 **파일을 읽어** 단언한다: ⓛ `.dockerignore` 가
   **빌드 컨텍스트의 뿌리에 있다** ⓜ 그 안에 **`.env` 를 빼는 줄이 있다** ⓝ **`Dockerfile` 이 이름으로
   `COPY` 하는 것을 빼는 줄이 없다**. **데몬을 요구하는 단언을 두지 않는다**(§0).
5. **변이로 값이 갈리는 것을 보인다**(§6-2 1, 작업 2 와 같은 규율): 최소한 `.env` 줄을 지운다 ·
   파일을 통째로 지운다 · `pyproject.toml` 을 빼는 줄을 넣는다. **한 자리씩 심고, 심기 직전의 작업
   트리 사본과 `diff` 로 적용을 확인하고, 그 사본으로 원복한다**(§6-2 규칙 5 — **이 커밋이 처음 넣는
   파일이라 `git diff` 는 지우는 변이에서 침묵한다**). 각 변이가 죽이는 단언의 이름과 값을 표로 남긴다.
6. **개수를 세지 않는다**(§6-1 9회차) — **이름**과 **부재**(위 2 의 마지막 줄)만 적는다.
7. **`Dockerfile` 을 만지지 않는다** — 소유가 없는 다른 자리이고 이 배정 밖이다.
   **`.gitignore` 도 만지지 않는다.**
8. **거짓으로 만드는 남의 자리**: ⓧ `.github/workflows/buildtwin-ci.yml` 의 `make env` 스텝 주석 —
   *"다만 이 저장소에 `.dockerignore` 가 없어 … 그 파일은 빌드 컨텍스트에 들어가고 `Dockerfile` 의
   `COPY . .` 가 이미지 레이어에 넣는다"*(**ⓑ 인용 · 발췌**, 소유 `qa` — **자기 소유**). 작업 5 가
   그 문장을 **거짓으로 만든다** → **같은 커밋에서 고친다**(§후속 76 · §6-4 1). ⓨ
   `tests/invariants/test_ci_builds_the_image.py` 머리의 「보지 못하는 것」 마지막 불릿(*"…담게 되는 것은 두 파일 어디에도 없다"* — 줄바꿈 한정은 §3-1-2 표) — **낡는가를 값으로 판정한다**: 새 불변식은
   **컨텍스트에서 빠지는 것의 선언**을 보지 **레이어에 담기는 것**을 보지 않으므로 나는 **낡지 않는다**고
   읽지만, 그 판정은 그 파일을 여는 사람이 값으로 다시 낸다(그 축이 §후속 94 다). ⓩ **그 밖에는 없다** —
   `README.md` 와 `Makefile` 에 `.dockerignore` 를 말하는 줄이 **하나도 없다**
   (**저장소 루트 `/home/user/Bim` 에서** `git grep -nI "dockerignore" 1e8fb19 -- .`, N=1 — `docs/` 밖
   히트는 위 ⓧ 그 주석뿐이고 **히트를 읽었다**. **같은 명령을 `buildtwin/` 에서 돌리면 히트 0 이다** —
   경로 지정자가 CWD 기준이다, N=1 · §후속 96). **그 값을 커밋 본문에 적는다.**

#### 3-2-1. §확인하지 않은 것 **79** — **짓는 축은 값으로 닫혔다. 서는 축은 열린 채다**

**한정어 역방향 확인**(§6-3) — 그 항목의 주어는 **`up --build`** 이고 새 잡이 부르는 것은 **`build`** 다.

#### 3-2-2. **ADR 0020 §2-1 항 2 는 거짓이 되지 않는다** — 확인했다

항 2 의 문안(**ⓐ** `grep -n "관측자 넷" docs/adr/0020-*.md`, **ⓑ 인용 · 발췌**): *"rc 를 갖지 않는

#### 3-2-3. §확인하지 않은 것 **90** 과 `test_demo_stack_can_stand.py` 의 그 불릿 — **낡지 않았다. 확인했다**

#### 3-2-4. **계획의 근거 하나가 거짓이었다** — 자리마다 판정한다(§M-12 의 네 축을 쓴다)

**qa 실측**(저장소 밖 사본, 각 **N=3**, compose **v5.1.1**; **저장소 밖 값이라 나는 다시 재지 못했다** —
§후속 62 대로 커밋 본문이 아니라 **그 값을 그 자리에 적은 워크플로 주석**을 읽었다,
**ⓐ** `grep -n "데몬 오류로 죽고" ../.github/workflows/buildtwin-ci.yml`):
`.env` 없이 `docker compose build` 는 `env file … not found` 가 **아니라 데몬 오류로** 죽고,

    그 파일이 말하는 「compose」가 어느 명령인지를 적을 것인가. *닫힘의 조건*: 어느 계획이 그 자리를
    배정하고 한정어가 들어갈 때. *한정*: **오늘 그 문장이 사용자를 잘못 이끄는 값은 없다** — 그 파일이
    말하는 경로는 사용자 갈래(`up`)이고 거기서는 참이다.

96. **`git grep <패턴> <트리> -- .` 의 경로 지정자가 CWD 기준이라 저장소 루트의 `.github/` 가
    조용히 빠진다**(architect + qa). **이 절이 그 함정에 실제로 빠졌다** — 값(각 N=1):
    `git grep -nI "dockerignore" 1e8fb19 -- .` 는 `/home/user/Bim` 에서 워크플로의 그 주석 줄들을 내고
    `/home/user/Bim/buildtwin` 에서 **히트 0** 이다. **같은 자리에서 두 번 물렸다**: 워크플로 인용
    `git grep -c "이 잡은 이미지를 푸시하지 않으므로" 1e8fb19 -- .` 도 `buildtwin/` 에서 **히트 0**,
    루트에서 **1** 이다(각 N=1). **예외도 던지지 않고 「없다」로 보인다** — 이 저장소의
    지배적 실패 모드 그 자체다. 그리고 **이 사이클의 ⓐ 참조 다수가 그 형태**다. *묻는 것*: ⓐ 참조가
    **어느 디렉터리에서 도는 명령인지**를 무엇이 싣는가(§후속 55 의 ⓐ 는 「그 자리에서 도는 참조」라고만
    적는다). *닫힘의 조건*: ⓐ 형식이 CWD 를 싣거나(예: 루트 고정 `-- :/`), 그것을 붙드는 게이트가 설 때.
    *한정*: **관측 1회**(이 절)다. §6-1 이 요구하는 *"목록은 저장소 루트에서 만든다"* 는 이미 있고,
    없는 것은 **그 명령이 루트에서 돌았음을 읽는 사람이 아는 방법**이다.

**확인하지 않은 것(신규):**

97. **[재지 않았다] 이미지 레이어 안에 `.env` 가 실제로 있는가.** 러너 로그가 보인 것은
    `.env` 생성 → 컨텍스트 전송 → `COPY . .` 까지다(§3-1-1 ㉯). **레이어를 연 사람이 없다** —
    여는 것은 데몬을 요구하고 이 환경은 `docker info` rc 1 이다(N=1).
    **[재야 한다 → qa · 데몬이 있는 자리에서 `docker run --rm <이미지> ls -l /app/.env` 또는
    `docker save` 의 레이어를 읽어]**
98. **[재지 않았다] 사용자의 기계에서 그 이미지가 남는가 · 얼마나.** 러너에서 잰 것은
    `naming to docker.io/library/buildtwin-{api,worker}` 까지이고 러너는 그 뒤 사라진다.
    **`.env` 를 지운 뒤에도 · `docker compose down -v` 뒤에도 그 이미지가 남는가**는 아무도 재지 않았다.
    **이 축이 ㉠ 판정의 무게가 걸린 자리다**(§3-1-4). **[재야 한다 → qa 또는 사용자 · 데몬이 있는 자리]**
99. **[재지 않았다] 러너의 compose 가 `.env` **없이** 어떻게 죽는가.** 첫 실행은 `make env` 를 먼저
    돌아 `.env` 를 가진 채 빌드했으므로 이 축을 가르지 못했다(§3-2-4 끝). 저장소 밖 사본에서 잰 값
    (compose **v5.1.1**: `build` 는 데몬 오류로, `config` 는 `env file … not found` 로 죽는다)이
    **러너의 판에서도 같은지** 모른다. **[재야 한다 → qa · `make env` 스텝을 잠시 뺀 실행 또는 러너의
    `docker compose version`]**
