## 👇 여기서부터 Claude Code에 붙여넣기

안건톡(건설 현장 업무 메신저) 기존 구현(REV9)에 REV10 변경분을 추가해줘.
REV10은 앱 최초 진입점이 되는 **회원가입·현장 등록 온보딩 흐름 전체**를 추가하는 작업이다. 지금까지는 이미 가입된 사용자를 전제로 홈(채팅 탭)부터 시작했는데, REV10부터 그 앞 단계인 온보딩이 생긴다.
REV10 디자인 레퍼런스: `design_handoff_angeontalk_REV10/anrgeontalk_wireframes_rev10.html` (모든 화면이 iPhone 390×844 프레임으로 한 문서에 배치, CSS는 `<style>`에 인라인, 화면 하단 `<script>`에 순수 JS 인터랙션). 온보딩은 문서 최상단의 **단일 인터랙티브 프로토타입 디바이스**로, 9개 화면을 단계 전환식(`.ob-step[data-step]`)으로 담았다.

기존 다크 테마, Pretendard 폰트, "상태 배지에만 색을 쓰는" 원칙, 큰 터치 타깃, 한글 UI를 유지하고, REV9까지 확정된 화면·레이아웃·색상·플로우는 건드리지 말 것.

상태색(공통): 검토중 주황 #f59e0b / 조치중 파랑 #3b82f6 / 완료 녹색 #22c55e / 사전검토 보라 #8b5cf6 / 관찰중 하늘 #0ea5e9. 브랜드 액센트(옐로우) #ffd60a는 CTA·포커스 한정.

**REV10은 화면 흐름과 로컬 상태 전환까지 구현한다.** 서버 저장·실제 인증 로직은 이번 범위에 포함하지 않는다.

### 배경 지식 (역할 체계)
- 국내 건설 현행법상 **건축·전기·통신·소방 4개 공종만 시공사**로 등록되고 발주처와 직접 계약한다. 그 외 공정(철근콘크리트·철골·외장판넬 등)은 이 4개 시공사 아래 **협력사(하청)**로 참여한다.
- 앱 사용자는 **발주처 / 한미글로벌 / 시공사 / 협력사** 네 역할 중 하나로 등록한다.
- 승인 주체가 다르다: **시공사는 한미글로벌**이, **협력사는 자신이 선택한 원청 시공사**가 승인한다.

### REV10 변경 요약 (신규 화면 9개)

**1. 시작 화면 (`data-step="splash"`)**
- 로고 마크 + 서비스명(안건톡) 중앙 배치, 태그라인("현장의 판단이 조직의 자산이 됩니다"), 하단 "시작하기" CTA.

**2. 역할 선택 (`role`)**
- "당신은 누구신가요?" + 4개 큰 세로 카드(발주처 / 한미글로벌 / 시공사 / 협력사), 각 아이콘·설명 한 줄. 탭 시 강조 테두리 후 현장 선택으로 진행.

**3. 현장 선택 (`site`) — 4역할 공통**
- "현장을 선택하세요" + 검색창 + 현장 목록. 기존 현장 탭 카드 스타일(썸네일·현장명·위치) 재사용하되 진행률·업데이트 배지는 생략.

**4. 가입 완료 (`done`) — 발주처·한미글로벌 전용**
- 현장 선택 직후 진입. 체크 아이콘 + "가입이 완료되었습니다" + 역할·현장 요약 + "시작하기"(홈 진입).

**5. 공종 선택 (`trade`) — 시공사 전용**
- "소속 공종을 선택하세요" + 건축·전기·통신·소방 2열 그리드. 이미 그 현장에 승인된 시공사가 있는 공종은 비활성 + "이미 등록됨"(한 현장·한 공종·한 시공사 원칙).

**6. 업체명 기입 (`cCompany`) — 시공사 전용**
- 현장·공종 요약 + 업체명 입력 + "승인 요청 보내기" → "한미글로벌 담당자에게 승인 요청을 보냈습니다" 다이얼로그 → 확인 시 승인대기(9).

**7. 원청 선택 (`origin`) — 협력사 전용**
- "소속 원청사를 선택하세요" + 그 현장에 등록된 시공사 카드(업체명·공종). 목업 2~3개.

**8. 공정 지정 + 업체명 (`pCompany`) — 협력사 전용**
- 현장·원청 요약 + 공정명 입력(자유 텍스트 + 추천 칩) + 업체명 입력 + "승인 요청 보내기" → "○○ 소장에게 승인 요청을 보냈습니다" 다이얼로그 → 확인 시 승인대기(9).

**9. 승인 대기 (`wait`) — 시공사·협력사 공통**
- 모래시계 아이콘 + "승인 대기 중입니다" + 신청 요약(역할·현장·공종/공정·업체명·승인대상) + 안내문 + 작은 "신청 취소". 승인 전까지 앱 실행 시마다 이 화면.

### 데이터 / 상태 모델 (REV10 추가분)
- **UserRegistration** 신규: `role`(발주처·한미글로벌·시공사·협력사), `site`, `trade`(시공사 공종) 또는 `proc`(협력사 공정), `corp`(업체명), `approver`(한미글로벌 또는 특정 원청 시공사), `status`(즉시가입 `active` / 대기 `pending` / 승인 / 거절).
  - 발주처·한미글로벌 → `status='active'` 즉시 완료. 시공사·협력사 → `status='pending'`로 시작.
- 레퍼런스 구현에서는 단일 `reg` 객체 + `goStep(name)` / `onEnter(name)`으로 단계 전환과 요약 채움을 처리한다.

### 진입 분기 (설계 반영, 저장/복원은 다음 REV)
앱 진입 시 로그인 상태를 확인해 분기: 미가입 → 시작 화면 / 대기(`pending`) → 승인대기 / 가입완료(`active`) → 기존 홈(채팅 탭). REV10에서는 실제 상태 저장·복원까지는 구현하지 않고 `status` 값으로 판단하는 흐름·전환만 완성.

### 구현 지침
- REV9 코드 구조/컴포넌트 패턴/상태관리/디자인 토큰 소스를 그대로 따라 신규 화면·상태 추가.
- 탭 전환/선택 카드 강조는 기존 패턴(프로필 상세 `.pf-tab`, 역할 카드 `.on`) 재사용.
- **협력사 원청 선택(7)과 시공사 공종 선택(5)의 목업 시공사 데이터는 일관되게** 사용(레퍼런스: 고창CDC 기준 동부건설/건축·대명전기/전기·세이프테크소방/소방이 등록됨 → 5에서 건축·전기·소방 비활성, 7에서 이 3개 노출).
- 다이얼로그·요약 채움은 화면 진입 시점에 상태에서 텍스트를 주입.
- 변경 후 REV9 화면 회귀 없는지 확인.
