# 현장 실무 계산기 — 정적 사이트

건설 공무·정비사업 실무에서 반복되는 계산을 도구로 만든 정적 사이트.
한 번 올려두면 손이 가지 않는 자산으로 두는 것이 목적이다.

## 왜 글이 아니라 계산기인가

2026년 3월 구글 코어 업데이트는 **대량 생산된 얇은 콘텐츠**를 정면으로 쳤다.
전문성이나 실경험 없이 양만 늘린 사이트가 크게 밀렸다.
구글이 금지한 것은 AI 사용 자체가 아니라 **가치 없는 양산**이다.

계산기는 그 반대편에 있다.

- 글이 아니라 **유틸리티**다. 양산 콘텐츠 판정과 무관하다.
- 검색해서 들어오는 사람의 **의도가 명확**하다. 트래픽이 적어도 전환된다.
- 별표5 구간이나 조합 직접출석 요건 같은 것은 **실무를 아는 사람만 만들 수 있다.**
  이게 곧 구글이 말하는 experience/expertise 신호다.
- 한 번 만들면 유지보수가 법령 개정 때뿐이다.

## 구조

```
src/shell.mjs        공통 HTML 껍데기(스타일·메타·애드센스 슬롯)
src/tools/*.mjs      도구 하나 = 파일 하나
build.mjs            dist/ 로 정적 페이지 생성
```

**도구마다 별도 URL을 갖는다.** 한 페이지에 계산기를 몰아넣으면
검색어 하나만 노리게 되어 손해다. 도구 3개면 노리는 검색어도 3개다.

## 빌드

```bash
node build.mjs      # → dist/
```

`dist/` 에 각 도구 페이지, 색인, `sitemap.xml`, `robots.txt` 가 생성된다.
빌드 산출물은 커밋하지 않는다.

## 도구 추가하기

1. `src/tools/` 에 모듈 파일을 하나 만든다. 기존 파일을 복사해 쓰는 게 빠르다.
2. 아래 필드를 채운다.

```js
export default {
  slug: "URL 경로",            // 한글 가능. 검색어와 같게 짓는다
  title: "탭·검색 결과 제목",   // 검색어를 앞에 둔다
  description: "검색 결과 설명문",
  h1: "페이지 제목",
  lede: "한 줄 설명",
  indexLabel: "목록에 뜰 이름",
  indexDesc: "목록 부제",
  body: `...HTML...`,          // 입력 폼 + 결과 영역 + 근거 + 해설
  script: `...JS...`,          // nf, krw(), $() 헬퍼를 쓸 수 있다
};
```

3. `node build.mjs` — 페이지·색인·사이트맵이 자동으로 따라온다.

`group` 필드를 넣으면 색인에서 그 분류 아래로 묶인다(`건설 공무`, `정비사업·공동주택`,
`노무`, `세무·금액`). 분류 순서는 `build.mjs` 의 `GROUP_ORDER` 에 있다.
새 분류를 쓰려면 거기에 이름을 추가한다. 빠뜨리면 목록 맨 뒤로 간다.

**해설 문단(`.explain`)을 빼지 말 것.** 계산기만 덜렁 있으면 검색엔진이
내용을 판단할 근거가 없다. "어떻게 계산하나 / 주의할 점"을 실무자 관점에서
직접 쓰는 것이 이 사이트가 다른 계산기와 갈리는 지점이다.

## 배포

정적 파일이라 어디든 올라간다. 무료 구간으로 충분하다.

1. **Vercel** 또는 **Netlify** 에 이 저장소를 연결한다. 설정 파일이 이미 들어 있다.
   - Vercel — 프로젝트 생성 시 **Root Directory 를 `tools-site` 로** 지정한다.
     나머지(빌드 명령·출력 폴더)는 `vercel.json` 이 처리한다.
   - Netlify — `netlify.toml` 에 base 까지 적혀 있어 저장소만 연결하면 된다.

   > 저장소 루트에 Next.js 앱(안건톡)이 함께 있다. Root Directory 를 지정하지 않으면
   > 그쪽을 빌드하려 하므로 반드시 `tools-site` 를 지정할 것.
2. 도메인을 연결한다. 광고를 붙이려면 자기 도메인이 사실상 필요하다.
3. `src/shell.mjs` 의 `SITE.origin` 을 실제 주소로 바꾼다.
   (정규 URL·OG 태그·사이트맵이 이 값을 쓴다.)
4. **Google Search Console** 에 사이트를 등록하고 `sitemap.xml` 을 제출한다.
   이걸 해야 검색에 잡히기 시작한다.

## 광고 붙이기

애드센스 승인은 **콘텐츠가 어느 정도 쌓인 뒤에** 신청한다.
도구 서너 개로 신청하면 대개 "콘텐츠 불충분"으로 거절된다.

승인 후 `src/shell.mjs` 의 `SITE.adsensePublisherId` 에 `ca-pub-...` 를 넣으면
모든 페이지에 스크립트가 자동으로 들어간다.

### 기대치

솔직하게 적어둔다. **도구 3~5개로는 광고 수익이 사실상 없다.**
한국어 실무 검색어는 검색량 자체가 작다. 광고만 보면 도구 20~30개에
검색 유입이 자리잡은 뒤에야 의미 있는 금액이 된다.

그래서 광고는 부수입으로 두고, **진짜 값어치는 유입구**에 있다고 본다.
계산기를 쓴 사람은 그 문서를 실제로 만들어야 하는 사람이고,
"이걸 만든 쪽이 문서 작성도 대행한다"로 이어지는 경로가 광고보다 크다.

## 도구 후보

만들어둔 것.

- [x] 건설기술인 배치기준 (별표5)
- [x] 하도급률
- [x] 조합 총회 직접출석 요건
- [x] 부가세 (공급가액 ↔ 합계액 역산)
- [x] 평 ↔ 제곱미터
- [x] 공사기간 (착공·준공일 → 일수)
- [x] 지체상금 (요율은 계약서 값 입력)
- [x] 설계변경 증감률 (증액 +, 감액 △)
- [x] 기성금 청구액 (선금 정산 공제)
- [x] 금액 한글 표기 (계약서용)
- [x] 면적 안분
- [x] 퇴직금 (평균임금 × 30일 × 재직일수/365)
- [x] 주휴수당 (주 15시간 요건·월 환산시간)
- [x] 연장·야간·휴일근로 가산수당
- [x] 일용직 소득세 (원천징수·소액부징수)

다음 순위. **법령·고시로 기준이 공개되어 있고, 실무자가 매번 다시 찾아보는 것** 위주로 골랐다.
착수 전에 각 항목의 근거 조문을 반드시 확인할 것.

**건설 공무**
- [ ] 하자담보책임기간 (공종별)
- [ ] 건설업 등록기준 자본금·기술인 수
- [ ] 산업안전보건관리비 계상 (공사종류·금액별 요율)
- [ ] 안전관리자·보건관리자 선임 기준
- [ ] 건설기계 임대차 표준계약 금액

**정비사업·공동주택**
- [ ] 총회 의결정족수 (안건 유형별)
- [ ] 조합 임원 선임 정족수
- [ ] 장기수선충당금 적립요율
- [ ] 입주자대표회의 구성원 수 산정

**노무·계약 일반**
- [ ] 4대보험 요율

한 번에 다 만들 필요는 없다. **한 주에 하나씩만 올려도 반년이면 20개가 넘는다.**
그리고 하나 만들 때마다 그 검색어가 하나씩 늘어난다.

## 계산 검증

```bash
node verify.mjs        # 계산식 검증
node browsercheck.mjs  # 실제 페이지 렌더 확인 (build 후)
```

`verify.mjs` 는 각 도구의 계산 로직을 알려진 값으로 대조한다. **도구를 추가하거나 상수를
고쳤으면 반드시 돌릴 것.** 계산기가 틀리면 사이트 전체의 신뢰가 무너진다.

### 브라우저에서도 한 번 열어볼 것

`verify.mjs` 는 계산식을 **다시 구현해서** 대조한다. 그래서 식이 맞아도
페이지 안 스크립트의 오타나 부동소수점 처리 차이는 잡지 못한다.
실제로 일용직 소득세에서 `verify.mjs` 는 1,350원으로 통과했는데
페이지에서는 1,349원이 나왔다. `(1 - 0.55)` 가 `0.44999999999999996` 이라
곱하는 순서가 달라 1원이 어긋난 것이다.

```bash
node build.mjs && node browsercheck.mjs
```

`browsercheck.mjs` 는 빌드된 페이지를 실제 브라우저로 열고, 확인하고 싶은 값을
입력란에 넣은 뒤 결과 영역의 텍스트를 찍는다. **도구를 추가하면 `CASES` 에
분기마다 한 줄씩 넣는다.** 특히 경고(`is-warn`)·안내(`is-ok`)로 갈리는 분기는
계산식 검증으로 확인할 수 없으므로 여기서만 드러난다.

출력은 통과/실패로 갈리지 않고 사람이 읽는다. 결과가 아예 계산되지 않았거나
입력 id 가 틀린 경우만 실패로 잡는다.

> 실제로 여기서 버그를 다섯 건 잡았다.
> 부가세 역산에서 `1,100,000 ÷ 1.1` 이 부동소수점 오차로 `999999.9999...` 가 되어
> 버림하면 공급가액이 1원 모자랐다. 유효자리로 정리한 뒤 버림하도록 고쳤다.
> 금액 한글 변환의 관행 표기에서 10,000 이 "일만"으로 나왔다. 만 자리는
> "만"으로 읽고 억·조는 "일억", "일조"로 읽으므로 만 자리에만 예외를 두었다.
> 건설기술인 배치기준 표가 별표5 원문과 달랐다. 전 구간이 한 등급씩 낮게
> 잡혀 있어 원문 대조 후 전부 고쳤다(2026-09-05 확인, 두 독립 출처 일치).
> 일용직 소득세는 `(1-0.55)` 부동소수점 오차로 1원이 모자랐다. 실효율을 한 번에
> 곱하고 유효자리로 정리하도록 고쳤다.
> `krw()` 가 만 단위 미만을 버리면서 154,800원을 "15만원"으로 단정해 보여줬다.
> 딱 떨어지지 않으면 "약"을 붙이도록 고쳤다.

## 유지보수

법령이 바뀌면 해당 도구의 상수만 고치면 된다.
값이 코드 상단 상수에 모여 있으므로 찾기 쉽다.

> 각 도구의 근거 조문은 페이지 하단에 표시된다.
> **개정 여부를 주기적으로 확인하는 것이 이 사이트의 유일한 정기 작업이다.**
