# 회의록 작성 (업종 무관)

회의 **오디오 전사본**을 받아 실무용 **회의록 DOCX**로 정리한다.
전사본은 STT 결과라 구어체·중복·오인식이 섞여 있으므로, 내용을 이해해
**안건 단위로 재구성**하는 것이 핵심이다.

업종에 따라 바뀌는 것은 **회의 주체 이름과 법정 기재사항뿐**이고,
안건 추출·요약·강조 규칙은 동일하다. 그래서 스킬은 하나이고 프로파일이 여럿이다.

## 프로파일 먼저 고른다

| 프로파일 | 대상 | 정족수 | 의결 결과 |
|---|---|---|---|
| `construction.json` | 건설현장 발주처–PM단(CM단) | — | — |
| `redevelopment-association.json` | 정비사업조합 총회·대의원회·이사회 | 기재 | 기재 |
| `apartment-council.json` | 공동주택 입주자대표회의 | 기재 | 기재 |
| `safety-committee.json` | 산업안전보건위원회 | 기재 | 기재 |

어느 회의인지 불분명하면 사용자에게 짧게 확인한다. 프로파일이 틀리면
강조 주체와 법정 기재사항이 전부 어긋난다.

**새 업종을 추가할 때는 스킬을 복제하지 말고 프로파일 한 장을 더 만든다.**

## 산출물 형식 (고정)

- **표 1개.** 컬럼: `No. | 안 건 | 핵심 내용 | 결론 및 조치사항`
- **참석자·날짜·장소·머리말은 넣지 않는다.** 제목과 표(+정족수)만 있는 순수 회의록.
- **강조 대상 주체의 지시사항은 `주체 →` 마커를 빨강 볼드로 표기**해 확실히 구분한다.
  강조 대상은 프로파일의 `roles.emphasis` 가 정한다(건설이면 발주처, 조합이면 조합).
- 그 외 주체의 마커는 남색.

## 작업 순서

1. 전사본을 읽고 **안건을 추출**한다. 화자 번호는 무시하고 발언 맥락으로 주체를 파악한다.
2. 안건마다 **핵심 내용**과 **결론**을 작성한다(규칙은 아래).
3. 프로파일이 정족수·의결을 요구하면 **성원 수와 안건별 찬반 수**를 받는다.
   전사본에 없으면 추측하지 말고 사용자에게 요청한다.
4. `data.json` 작성 후 실행한다.
5. **렌더링 검증**: PDF로 변환해 표·한글·강조가 깨지지 않았는지 눈으로 확인한다.
6. 출력 폴더로 복사하고 `present_files` 로 제시한다.
7. **오인식·불확실 항목은 별도로 짚어 사용자 확인을 받는다.**

## 핵심 내용 작성 규칙

- **1~3줄, 되도록 2줄 이내.** 압축·정확이 우선.
- 무엇에 대한 안건인지 + 배경/제안 요지 + 정량 정보(금액·수량·규격).
- 금액 증감은 부호로: **증액 `+6,300만원`, 감액 `△3,700만원`**.
- 제안 주체를 밝힌다.

## 결론 작성 규칙

결론은 **강조 주체가 지시·결정한 내용** 또는 **다른 주체가 어떻게 하겠다는 조치**로 쓴다.
한 안건에 결론이 여러 개면 배열로 나열한다.
`who` 값은 프로파일 `roles.known` 을 따른다.

## 정족수와 의결 결과

정족수를 켠 프로파일에서는 표 위에 성원 줄이 들어가고,
`총 조합원 수` 와 `직접 출석` 이 있으면 **직접출석 비율을 자동 계산**해 함께 적는다.

> **조합 총회에서 직접출석 비율은 결의 효력과 직결된다.**
> 일반 안건 10% 이상, 창립총회 및 정비사업비의 사용·변경 안건은 20% 이상이 요구된다.
> 비율이 요건에 못 미치면 회의록을 넘기기 전에 반드시 사용자에게 알린다.
> 조문과 해당 조합 정관은 인용 전 현행 기준으로 확인한다.

## data.json 스키마

```json
{
  "profile": "redevelopment-association.json",
  "title": "총 회 의 사 록",
  "quorum": { "총 조합원 수": 486, "출석(서면 포함)": 351, "직접 출석": 62 },
  "items": [
    {
      "title": "시공자 선정 계약 체결의 건",
      "core": "입찰 3개사 중 우선협상대상자 선정 결과 보고. 공사비 평당 690만원.",
      "conclusions": [
        { "who": "조합", "text": "계약 체결 승인. 물가변동 조정은 착공 후 24개월 이후분에만 적용." },
        { "who": "집행부", "text": "계약서 최종안을 차기 대의원회에 보고 후 날인." }
      ],
      "resolution": { "찬성": 312, "반대": 31, "기권": 8, "결과": "가결" }
    }
  ]
}
```

`title` 미지정 시 프로파일의 `docTitle` 을 쓴다.
`quorum`·`resolution` 은 프로파일이 꺼져 있으면 무시된다.

## 실행 & 검증

```bash
cd <스킬디렉토리>
npm install                 # 최초 1회 (docx)
node scripts/build_minutes.js data.json 회의록.docx

# 프로파일을 파일 밖에서 지정할 수도 있다
node scripts/build_minutes.js data.json 회의록.docx --profile construction.json

# 렌더링 검증
soffice --headless --convert-to pdf --outdir . 회의록.docx
pdftoppm -jpeg -r 110 회의록.pdf page   # page-*.jpg 를 눈으로 확인
```

예시 입력은 `examples/association-sample.json` 에 있다.

## 파일명 규칙

`YYMMDD_조직약칭_회의명.docx` (예: `260701_○○구역조합_정기총회.docx`).
날짜·조직을 모르면 사용자에게 확인하거나 전사본 제목에서 추출한다.

## 스코프 판단

- 회의 목적과 무관한 잡담은 **안건에서 제외**한다.
- 애매하면 넣지 말고, 제외한 주요 화제는 응답에서 한 줄로 알려 사용자가 판단하게 한다.

## STT 오인식 주의

전사본에서 전문용어가 틀리게 적히는 경우가 많다(예: "관광 아르식" ← 강관 발열식).
문맥으로 교정하되, **교정한/불확실한 용어와 정량치(수량·금액·표결 수)는
회의록 제시 후 별도로 짚어 확인**을 받는다. 특히 표결 수는 절대 추측하지 않는다.
