# 현장 문서 자동화 — 설치 패키지

건설 현장의 반복 문서를 자동 작성하는 스킬 묶음을, **현장마다 재사용할 수 있는 형태**로
정리한 곳이다. 스킬 본문에는 현장 고유값을 두지 않고, 현장별 값은 전부 프로파일 한 장에 모은다.

앱 쪽의 `lib/siteConfig.ts` 와 같은 원리다. 바뀌는 것을 한곳에 모아야 다음 현장에 팔 수 있다.

## 왜 이렇게 하나

대행(Tier 0)은 소득이 작업 시간에 비례한다. 고객이 늘면 내 시간도 그만큼 늘어난다.
**설치형으로 팔아야 소득이 시간에서 분리된다.** 그 전제가 "스킬이 남의 현장에서도 도는 것"이고,
그러려면 현장 고유값이 코드에서 빠져 있어야 한다.

부수 효과가 하나 더 있는데, 이쪽이 영업에서 더 크게 먹힌다.

> **파일을 보내지 않아도 된다.** 고객사 PC 안에서 실행되므로
> 도면·계약금액·협력사 단가가 사무실 밖으로 나가지 않는다.

대형 현장은 발주처 자료를 반출할 수 없다. 대행 모델의 천장이 여기인데,
설치형은 그 제약을 그대로 장점으로 바꾼다.

## 구성

| 파일 | 용도 |
|---|---|
| `project.schema.json` | 현장 프로파일 스키마 |
| `profiles/example-site.json` | 가상 현장 예시 — 새 현장은 이걸 복사해서 시작 |
| `PORTABILITY.md` | 스킬별 이식성 실사 · 견적 산식 · 온보딩 체크리스트 |

## 새 현장 온보딩

1. **자료 수령** — `PORTABILITY.md` 의 온보딩 체크리스트대로 받는다.
   완성된 산출물 견본과 실제 문서번호 20건이 특히 중요하다. 견본 없이 시작하면 반드시 두 번 만든다.
2. **프로파일 작성** — `profiles/example-site.json` 을 복사해 값을 채운다.
3. **검증** — 받은 문서번호 20건을 파서에 넣어 발신/공종/번호가 제대로 갈리는지 본다.
   여기서 안 걸리는 예외는 납품 후에 반드시 걸린다.
4. **시범 산출** — 각 문서 1건씩 만들어 견본과 나란히 놓고 확인받는다.
   PDF로 변환해 표가 깨지지 않았는지 눈으로 본다.
5. **인계** — 담당자 자리에서 직접 돌려보게 하고, 한 달 뒤 다시 본다.

## 원칙

- **값을 추측해서 채우지 않는다.** 서류에서 확인되지 않는 항목은 공란으로 두고 알린다.
  검토서에 틀린 값이 한 번 들어가면 그 현장은 다시 쓰지 않는다.
- **양식을 새로 만들지 않는다.** 고객이 쓰던 서식을 그대로 재현한다.
  새 양식을 배우게 하는 순간 도입이 멈춘다.
- **프로파일에 실제 협력사 정보를 커밋하지 않는다.** 이 저장소에는 가상 예시만 둔다.
  실제 현장 프로파일은 해당 고객사 안에서만 보관한다.
