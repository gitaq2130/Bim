## 👇 여기서부터 Claude Code에 붙여넣기

안건톡(건설 현장 업무 메신저) 기존 구현(REV6)에 REV7 변경분을 추가해줘.
REV7은 3가지 — ① 연락처 그룹핑을 공종별/업체별 토글로 확장, ② 내 명함 편집 화면의 입력 필드 분리, ③ 메시지별 안읽음 인원수 표시 — 를 반영하는 작업이다.
REV7 디자인 레퍼런스: `design_handoff_angeontalk_REV7/anrgeontalk_wireframes_rev7.html` (모든 화면이 iPhone 390×844 프레임으로 한 문서에 배치, CSS는 `<style>`에 인라인, 화면 하단 `<script>`에 순수 JS 인터랙션).

기존 다크 테마, Pretendard 폰트, "상태 배지에만 색을 쓰는" 원칙, 큰 터치 타깃, 한글 UI를 유지하고, REV6까지 확정된 화면·레이아웃·색상·플로우는 건드리지 말 것.

상태색(공통): 검토중 주황 #f59e0b / 조치중 파랑 #3b82f6 / 완료 녹색 #22c55e / 사전검토 보라 #8b5cf6 / 관찰중 하늘 #0ea5e9. 브랜드 액센트(옐로우) #ffd60a는 CTA·포커스 한정.

### REV7 변경 요약 (이 3가지만 구현)

---

**1. 연락처 탭 — 공종별/업체별 그룹핑 토글 (화면14 수정, 레퍼런스 화면14)**

기존 화면14 상단의 "최근 대화순 / 가나다순" 정렬 토글을 "공종별 / 업체별" **그룹핑 토글**로 교체한다(pill 버튼 2개 패턴 재사용). 기존 정렬 기준(가나다순 등)은 각 그룹 **안에서의 정렬**로 한 단계 내려서 작은 보조 토글/드롭다운으로 유지.

- **공종별 보기**(기존): 🔨 건축 3명 / 🔧 설비 2명 그룹, 각 사람 항목 우측에 **소속회사 배지**.
- **업체별 보기**(신규): **회사명으로 그룹핑**, 각 사람 항목 우측에 **공종·파트 배지**(배지 위치는 공종별과 동일, 내용만 반대 전환).
  예: 🏢 동부건설 2명 → 김성호 소장(🔨 건축), 박정민 부장(🔨 건축) / 🏢 삼우이엔지 1명 → 이형탁 소장(명함 미등록) / 🏢 한양기공 1명 → 최재원 과장(🔧 설비) / 🏢 세진소방 1명 → 정우진 대리(🔧 설비, 명함 미등록).
- **명함 미등록 배지**, **"전체 연락처 N명 · 명함 등록 M명" 카운터** 등 기존 로직은 두 그룹핑 모드 모두에서 동일하게 유지(카운터·미등록 배지 공통).

**2. 내 프로필 편집 — 입력 필드 분리 (화면17 수정, 레퍼런스 "내 명함 편집")**

기존 "직급 / 소속" 한 칸짜리 자유 텍스트 입력을 **이름 · 직급 · 회사 · 파트 4개의 독립 필드**로 분리(각 필드 기존 다크 인풋 스타일, 세로 순서 배치).

- **회사·파트 필드**는 연락처 리스트의 소속회사 배지 / 공종·파트 배지와 **1:1 매핑**되는 데이터 — 이 두 필드 값이 그대로 배지에 사용됨.
- **표시 시에는 조합**: 프로필 헤더·리스트 항목 등 기존에 "이름+직급"을 한 줄로 보여주던 곳("김성호 소장")은 **이름 필드 + 직급 필드**를 조합해 표시, 회사·파트는 각각 별도 배지로 표시. 저장은 4개로 나뉘지만 표시 방식(조합형 타이틀 + 배지 2개)은 REV6과 동일.
- 명함 촬영/업로드, 휴대전화, 이메일, 안건톡 활동 공개 토글 등 나머지는 기존과 동일 유지.

**3. 메시지별 안읽음 인원수 표시 (화면2·화면4 수정)**

공종방(화면2)·안건방(화면4) 양쪽 적용.

- 각 메시지 말풍선 옆(시각 표시와 같은 줄, 시각 바로 위쪽)에 작은 숫자로 안읽은 인원수를 **노란색 #ffd60a**로 표시.
- 모두 읽으면(0) 숫자는 표시하지 않음.
- 숫자를 탭해도 **열람자 명단은 노출하지 않음** — 개인별 열람 여부·응답 속도는 인사평가로 오해될 수 있어 표시하지 않는다는 기존 원칙 유지. 숫자만 보여주고 그 이상 상호작용 없음.

### 데이터 / 상태 모델 (REV7 추가분)
- **연락처(Contact)**: 그룹핑 축 2개(공종/업체) 필요 — 하나의 텍스트 필드였다면 `part`(공종)와 `company`(회사)를 독립 필드로 분리.
- **프로필(Profile)**: `name`, `title`(직급), `company`(회사), `part`(파트) 4개 독립 필드로 분리. 기존 "직급/소속"이 단일 문자열이었다면 REV7 전에 마이그레이션 필요 — 구분이 안 되어 있으면 구현 전에 알려줄 것.
- **메시지(Message)**: `unreadCount`(숫자) 파생 상태 — 방 참여자 수 대비 읽음 처리 인원수 차이로 계산.

### 구현 지침
- REV6 코드 구조/컴포넌트 패턴/상태관리/디자인 토큰 소스를 그대로 따라 신규 상태·필드 추가.
- 그룹핑 토글은 기존 정렬 토글 UI 패턴(pill 버튼 2개) 재사용.
- 변경 후 REV6 화면 회귀 없는지 확인.
